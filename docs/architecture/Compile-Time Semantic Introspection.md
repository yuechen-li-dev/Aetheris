# Compile-Time Semantic Introspection

Firmament schema is an opt-in, static description of the public authoring surface. It does not perform runtime reflection, mutate semantic objects, or replace the parser and binder.

`Aetheris.Firmament.SchemaGenerator` is a Roslyn incremental source generator. It visits classes marked with `FirmamentConstructAttribute`, reads explicit `FirmamentFieldAttribute` and `FirmamentOutputAttribute` declarations, validates stable IDs and supported kinds, sorts by stable ID, and emits `FirmamentSemanticSchemas.g.cs`. The generated file is inspectable at `Aetheris.Kernel.Firmament/obj/Generated/Aetheris.Firmament.SchemaGenerator/Aetheris.Firmament.SchemaGenerator.SemanticSchemaGenerator/FirmamentSemanticSchemas.g.cs` after a build. It is excluded from source control with `obj/`.

The generated registry contains read-only `FirmamentConstructSchema`, `FirmamentFieldSchema`, and `FirmamentOutputSchema` descriptors. IDs are explicit construct, field, and output keys; field/output IDs are qualified by construct ID. They do not depend on declaration or hash iteration order. Unit kind is derived from Length or Angle value kinds, or declared explicitly for a vector or point such as Box Size. Descriptors contain no callbacks, UI layout, runtime setters, or CLR member names. `FMS001` is a build error for duplicate/missing construct or field IDs, duplicate construct names, unsupported kinds, incompatible units, invalid choice declarations, and duplicate output IDs.

The schema is available to the browser through versioned `language.schema()` transport. Its JSON uses semantic strings for kinds and units. The existing `language.complete()` path takes Helix and solid Loft fields from the generated descriptors. It still uses parser-owned context detection. The Web tree preserves its existing body `kind` and separately projects the parser's `semanticConstruct` for schema lookup. Helios shows generic field and output metadata for a selected construct when that identity matches a schema; it never edits the compiled object through schema metadata.

This first slice has a deliberate boundary. Box and Hole descriptors are informational, while their parser rules remain separately implemented. Concept requirements are user-defined members, so Concept has a construct descriptor but no fixed field list. The current Web session does not provide a general semantic-instance-to-authored-field projection or per-field source span. Helios therefore labels unavailable values explicitly and only links fields to source when the existing SDK property supplies a range. Generic Inspector editing from the schema is disabled. The pre-existing experimental effective override editor remains separate and is not schema authority.

The schema path uses ordinary generated C# and static collection access. It does not scan assemblies, use `PropertyInfo`, call `MethodInfo`, invoke `dynamic`, or require runtime reflection metadata preservation. The existing Web host's JSON transport still uses reflection-enabled serialization; that broader host has IL2026 trim warnings. NativeAOT compatibility of the broader runtime still requires its normal qualification path; the schema introduces no reflection-specific preservation requirement.
