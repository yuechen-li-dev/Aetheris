# FIRMAMENT-FRONTEND-X0 — compiler honesty qualification

Date: 2026-10-14. Executive verdict: **Meaningful progression; not Accepted.**

The generic mechanical path now closes reproduced parse-failed/valid reporting,
capability/selection validation gaps, implicit V1 fallback, unknown canonical
Model/Modify statements, unknown Box fields, and ignored profile-layout XZ frames.
It preserves semantic-selection explanations and identifies the enclosing Model.
It does **not** establish closed source consumption across the advanced
Compose/boundary family or every specialized domain. The non-negotiable universal
source-intent invariant therefore remains unqualified.

## Root causes and repairs

1. The validation report derived success solely from a fatal-code count. Parse
   failure now makes the report invalid independently of its diagnostic spellings.
2. Parser/binder strings crossed several severity adapters, each with its own
   fatal-prefix list. The existing adapter now assigns severity once: known
   informational trace events remain information, the deliberate nominal-only
   tolerance warning remains a warning, and unclassified diagnostics are errors.
   Parser completion enforces that severity. The former error allowlists were
   removed, including the Concept-specific one.
3. The mechanical exporter could retry materializers or V1 after failed parsing.
   RecognizedInvalid now prevents V1 retry. A trial gate before all mechanical materializers was backed out after it rejected established profile-boundary fixtures; those adapters retain their existing owner-specific admission.
   Serialization-shaped roots are classified before expansion, so V2 keywords used as V1 data (tested with model names Model and Template) cannot hijack routing. Explicit version-1 file compatibility remains on its existing reader; canonical
   in-memory compilation retains its V2 firewall. Dedicated Revolve/Sweep/WireForm
   and other domain owners retain their own admission paths.
4. Generic validation stopped before build capability and topology selection
   binding. FirmamentBuildAdmissionValidation calls existing CompileSource,
   including in-memory materialization/export and build assertions. It does not
   create another validator or write STEP files. Static-only validation and
   externally loaded Forge descriptors report parsed-not-built explicitly.
5. The canonical root scan was line-anchored, and Modify lacked a closed neighbour
   check. Their existing owners now use the existing lexer and balanced block
   boundaries. Primitive field checking reuses generated field metadata where it
   exists (notably Box). This is not complete per-route field consumption.
6. Profile frame lookup defaulted unresolved named frames to WorldXY. It now
   resolves declared XY layouts, rejects unsupported On XZ, rejects unknown frames,
   and retains traced Construction Plane resolution.
7. Semantic-selection exporters replaced detailed resolver diagnostics with only
   the failure enum. They now retain code and message. Through-Pocket diagnosis
   names the admitted through-cut mechanism. Generic build summaries project
   DocumentName instead of the last materialized feature identity.
8. A canonical Pocket witness reused its boundary's display name. The symbol
   binder already permitted typed Profile/Boss/Pocket name sharing; that same
   rule now includes ClosedBoundary2/Polygon2 construction inputs. This preserves
   admitted engineering semantics without suppressing duplicate-name errors.

## Diagnostic and validation contract

Generic V2 errors are objects with code, severity, message, sourceFile, optional
sourceSpan, line/column, stage/source and locationNote. Legacy `fatal` means error;
warning/info remain nonfatal. Existing dynamic code suffixes are retained for
compatibility. Kernel-only failures without a specific diagnostic ID retain their
KernelDiagnosticCode; legacy bare semantic codes are preserved as codes.

Unknown field/statement diagnostics can identify an unambiguous original token.
Other legacy producers receive a document declaration anchor with an explicit
limitation note. No claim is made that an expanded-source offset is an exact
original-source location. Schema selector erasure preserves character/newline
offsets; the CLI presents diagnostics against author source rather than expanded
library text. Full include/expansion origin mapping remains an X1 prerequisite.
The language service uses the same presentation for parser diagnostics; hover,
completion and last-valid-model retention were not redesigned. An independent
Helios application run was not performed; no files in that repository were changed.

Normal generic mechanical `valid` requires successful existing engineering
compilation in the current environment, with validationLevel Built. Rejection is
invalid / BuildRejected (or invalid at the earlier static stage). ParsedNotBuilt
never claims build admission. --explain exposes actual branch metadata and
available template/solid counts, not a fabricated expansion tree. Specialized
domain validators retain their narrower current contracts and legacy JSON shapes.

## Remaining blocker and smallest prerequisite

Two retained advanced witnesses still accept intent they do not execute:

- unknown-compose-statement inserts `Fillet LostIntent { Radius: 1mm }` into an
  otherwise admitted Compose. The operation parser searches for recognized
  matches; it does not account for the remaining tokens.
- unknown-boundary-field adds `heigth: 99mm` to a Rect2 consumed by Compose.
  ClosedBoundary2Authoring and subsequent guide readers bind their known fields
  without retaining field-consumption receipts. The extra field disappears.

These are open correctness defects, not compatibility aliases. Shared build
preflight cannot detect intent that both parser and build have discarded. Further
global keyword/field scans would duplicate partial grammars, and a new global
rewrite or fatal-code allowlist would violate X0's ownership rules.

A trial early gate also failed the established ProfileBoundaryChamferFixtureTests junction selections (for example ReflexNotch and CornerPair) with firmament-v2-selection-malformed, and ProfileBoundaryAuthoringTests derived profiles with canonical-document-malformed. Their existing production owners successfully build geometry with pinned topology/volume expectations. The generic parser cannot be made the sole gate without first projecting those existing admitted constructs. The trial gate was removed instead of adding diagnostic exemptions or breaking those fixtures.

The smallest next unit is **project existing profile junction/derived-profile admission into the generic document contract, then add consumed-token/field spans and original-source origin
receipts for the CanonicalAdvanced Compose/ClosedBoundary2 adapters, checked
before erasure**. Establish them with the two specimens, then extend the same
contract through Feature/Template/Pattern. This can be the first bounded X1
prerequisite; it does not require replacing engineering lowerers or adding a new
kernel capability. Full unified parsing remains shadow-mode work.

## Compatibility and code-quality review

No new regex call site, whole-document dispatcher, text substitution pass,
product-side validator, geometry operation or mutable parser-state mechanism was
introduced. Existing root/Modify ownership checks use lexer spans. The existing
small parse cache remains; per-parse source and route metadata are immutable.
Diagnostic severity/message mapping is consolidated in the existing adapter.
Engineering feature identities and STEP geometry are not renamed to fix summaries.

The Cadmata split-compose-chamfer fixture used an undeclared ComposeGuide frame. Unknown-frame rejection exposed it; the fixture now states Using XY explicitly, preserving its previously defaulted world plane. The seven compiler-body/published-correspondence integration cases passed after this correction. No special case for the fixture name was added to the compiler.

The public schema Revolve and casing documentation contradictions were corrected.
Historical reconciliation “resolved” rows are qualified by this report and the
October decision register. Geometry placement F12 and unconsumed advanced fields
are explicitly retained as unresolved, not hidden behind green test results.

## Executive answer

generic validation/fallback/frame/diagnostic defects are repaired and bounded
source tests prove the improvement. CanonicalAdvanced still has concrete ignored
intent witnesses, specialized diagnostic shapes remain inconsistent, full
expansion provenance is unavailable, and the original twelve programs were not
provided. X0 must remain open until consumed-source admission closes those gaps.
