# Firmament language service X2

Firmament language intelligence is owned by `Aetheris.Kernel.Firmament`. `FirmamentLanguageService` supplies schema-backed completion. `FirmamentLanguageAnalysisService` supplies token spans, parser diagnostics, hover, bounded source definition, and formatting. These APIs run without BRep materialization and are exposed by `Aetheris.Web.Runtime` as `languageComplete`, `languageAnalyze`, `languageHover`, `languageDefinition`, and `languageFormat`. The npm SDK forwards those operations. Helios calls the page-thread Web/WASM runtime; geometry builds remain in its Worker. The result records carry document, source revision, and offsets so a later LSP adapter can translate them without owning Firmament semantics.

Completion uses generated `FirmamentSemanticSchemas` and existing construct authoring helpers. Model-scope prefixes include legal entry scaffolds for nested constructs such as Helix and Loft. Thread, Perforation, Helix, Loft, Box, and Hole fields are context filtered; bounded choices come from field schema. Selector candidates remain compiled semantic identities in the client, with RuntimeOnly topology excluded.

Analysis classifies source spans in Aetheris and takes live errors from `FirmamentV2Parser.Parse`; it does not run the geometry pipeline. Current source navigation resolves a uniquely named construct declaration in the same source. Hover covers generated construct and field descriptions. The lexical span mapper and declaration lookup are bounded initial projections; they are not a second parser, and they do not claim full symbol resolution or cross-file navigation.

`Format` is one opinionated whitespace formatter in Aetheris. It requires parser admission before and after, preserves token text including comments, and is tested for idempotence and a simple Box model's semantic fields. That is not yet a broad semantic-equivalence proof for all Firmament constructs. Helios therefore exposes Format Document but leaves format-on-build disabled. The formatter refuses invalid input; build always receives the authored source.
