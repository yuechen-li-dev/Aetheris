# Templates and static data

Templates are typed compile-time functions over engineering values and Records. `Static` binds immutable values, arrays, or Tables; `Pattern ... Over` repeats an admitted feature from finite static data. `Require` constraints fail before geometry when a specialization is inadmissible.

Build [`record-array-pattern-holes.firmament`](../../../fixtures/Canonical/valid/record-array-pattern-holes.firmament) for the shortest array/Template/pattern example. [`table-template-concept-path-compose.firmament`](../../../fixtures/Canonical/valid/table-template-concept-path-compose.firmament) adds a keyed Table and profile composition. For Sheet Metal product families, see [`m5-four-wall-tray-template.firmament`](../../../fixtures/SheetMetal/m5-four-wall-tray-template.firmament).

Unknown Templates, missing arguments, extra fields, wrong unit dimensions, and failed `Require` constraints are errors. Template expansion does not create a second geometry or diagnostic path: expanded source uses the same binder and materializers as direct source.
