# X3 — Piping and local autorouting

> Follow-up: [X3a equipment port and nozzle connection hardening](X3A-EQUIPMENT-PORT-NOZZLE-CONNECTION-HARDENING.md) closes the flagship's proxy-to-pipe visual gaps with equipment-owned nozzle stubs and target-scoped KeepOut exemptions.

## Executive verdict

**Accepted.** Aetheris can represent logical piping connections independently of geometry, author or deterministically propose orthogonal routes, accept proposals into ordinary semantic route state, locally replace a bounded interval while preserving the remainder, realize hollow analytic pipe/fitting components, and emit deterministic fabrication reports plus an AP242 assembly.

This is bounded skid-scale routing, not industrial plant routing.

## Architecture

```text
PipingSystem
→ logical Connection between port Interfaces
→ explicit Route or RouteRequest
→ inspectable RouteProposal
→ accepted ordinary Route
→ Elbow90 fittings + hollow PipeSegments
→ AP242 occurrence Assembly
→ semantic BOM + pipe Cut List + routing JSON
```

X2's Interface and assembly doctrine is reused. A piping port is `PipingPortInterfaceIr`: stable identity, position/DatumFrame, outward direction, circular policy, and connection style. There is no second piping-only endpoint identity beneath it. The older `Aetheris.Piping` module remains the lower-level bounded analytic route capability; X3 adds the Firmament system graph, authoring, router, fabrication model, and assembly path without changing that module's public contracts.

Accepted state is `RouteIr`, regardless of whether its provenance is `Explicit`, `AutoGenerated`, or `LocallyRerouted`. The geometry path consumes only `RouteIr`. A proposal is copied into stable route anchors by `OrthogonalAutoRouter.Accept`; it is not stored as an opaque solver object and no router call is needed to rebuild a materialized explicit route.

## Router

The router uses a bounded adaptive coordinate grid, not uniform voxelization.

- Candidate coordinates: source/destination coordinates, hard-waypoint coordinates, bend-aware obstacle min/max faces, and one deterministic exterior margin plane on each axis. Corner planes include a bend-radius planning margin; planes too close to a required point to fit adjacent tangent setbacks are removed.
- Obstacles: axis-aligned semantic `KeepOutIr` bounds inflated by `pipe OD / 2 + requested clearance`.
- Graph: Cartesian coordinate intersections outside inflated interiors; edges connect adjacent visible coordinates along `±X`, `±Y`, or `±Z`.
- Search: A* over `(node, incoming direction)` state.
- Cost: `route length + 1000 mm × elbow count`. The elbow penalty deliberately dominates small length savings.
- Endpoint policy: the first edge equals the source outward direction; the final edge equals the negative destination outward direction.
- Determinism: fixed direction order (`+X,-X,+Y,-Y,+Z,-Z`) and priority tie-breaking by estimated cost, turns, traveled length, node ordinal, then direction.
- Simplification: duplicate and collinear nodes are removed before proposal materialization.

The current bounded AABB query is exact for the admitted KeepOut representation, so X3 did not force obstacles through CIR merely to rename the same calculation. CIR remains the intended query adapter when routing admits non-box implicit obstacles; final BRep authority remains AIR/construction-derived.

Failures distinguish endpoint-direction impossibility, excessive clearance, unreachable hard waypoints, disconnected routing space, no collision-free path, and locked-interval conflicts.

## Geometry and clearance

Every straight run is shortened to fitting tangent points and becomes an independent hollow analytic-cylinder `PipeSegment`. Every turn becomes an independent hollow `Standard.Piping.Elbow90` with outer and inner analytic torus surfaces plus annular planar ends. OD, wall thickness, bend radius, material, named fitting Interfaces, centerline length, and cut length remain semantic fields.

Planner visibility uses obstacles inflated by pipe radius plus requested clearance, while candidate corner planes add a bend-radius margin. After materialization, an independent pass computes exact axis-aligned straight-run distance to each original KeepOut and samples every realized torus centerline deterministically, subtracting both pipe radius and the maximum sampling-chord sagitta. The result is a conservative lower bound for the actual cylinder/elbow envelope, not a zero-radius polyline check. Routing clearance and the kernel tolerance context remain separate quantities.

KeepOut proxies are emitted as distinct named AP242 components to make the inspection artifact intelligible. They are routing proxies, not detailed pumps, heat exchangers, or structural designs.

## Local rerouting witness

The canonical local witness begins with:

```text
[0,0,0] → [500,0,0] → [500,300,0]
→ [500,300,300] → [1000,300,300]
```

Segment 2 (the vertical riser, using zero-based ordinals) is locked. `LocalReroute AroundMotor` authorizes anchors `0..2`; segment 2 begins at the exclusive interval boundary and is therefore preserved. The accepted result changes only that prefix interval and retains the suffix points exactly:

```text
[500,300,300] → [1000,300,300]
```

The lock is shifted to the corresponding final segment without changing its endpoints. Regression tests assert `LocallyRerouted` provenance, exact suffix points, preserved lock, stable port Interfaces, and rejection when an authorized interval crosses a lock.

## Standard Library, CLI, Forge, and inspection

The embedded Standard source ships generic `Pipe`, `Elbow90`, `Tee`, and `PumpSkid` policies. `Use Standard.Piping` resolves them through normal X1a semantics. Forge Protocol v1 exposes `Standard.Piping.PumpSkid` through the existing `list`, `describe`, and `invoke` operations; no piping RPC was added.

`aetheris inspect --json`, `validate --json`, and `build --json` report the PipingSystem, policies, ports, Connections, KeepOuts, proposals, accepted Routes, PipeSegments, fittings, BOM, Cut List, clearance evidence, analytic surface counts, bounds, timings, and AP242 evidence. The ordinary assembly/product structure remains visible to existing STEP/Cadmata inspection.

## Limitations and follow-up

X3 intentionally does not implement 45-degree elbows, freeform/spline routing, arbitrary bend fabrication, automatic tee branch realization, automatic reducers/flanges/adapters, standards dimensions or pressure classes, penetrations, supports, anchors/guides, spools, slope, stress, flow, pump sizing, or plant-scale routing. The shipped Tee policy is an architectural product hook; automatic branch graph lowering is future work.

Preference regions and CIR-backed non-box distance queries are deferred until a real admitted obstacle family needs them. Equipment and frame bodies in the flagship are conservative proxies. Route search is bounded by the candidate-coordinate graph and is not complete over arbitrary continuous geometry.
