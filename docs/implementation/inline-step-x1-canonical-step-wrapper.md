# INLINE-STEP-X1 canonical STEP wrapper

INLINE-STEP-X1 adds the smallest Firmament V2 path for wrapping one existing Aetheris-canonical AP242 STEP body and re-exporting it through the real Aetheris import/export pipeline.

## Syntax

The supported syntax follows the existing Firmament V2 typed-record style:

```firmament
solid importedPart: InlineStep {
    path: "../testdata/canonical-box-10x8x6.step"
}
```

The symbol name (`importedPart`) is preserved as the exported STEP product name. The `path` is preserved in the parsed InlineStep record along with a normalized path, SHA-256 content hash, canonical-input flag, and canonical evidence string.

## Canonical STEP requirement

Inline STEP input must be Aetheris-canonical AP242. Raw external/vendor STEP remains import/canon input, not Firmament source. The intended flow is:

```text
external/vendor STEP -> aetheris canon -> Aetheris-canonical STEP -> Firmament InlineStep -> AP242 re-export
```

X1 detects canonical input using the current Aetheris exporter header evidence:

- `FILE_DESCRIPTION(('Aetheris AP242 subset export'), ...)`
- `FILE_NAME(... 'Aetheris.Kernel','Aetheris.Kernel', ...)`
- AP242 managed-model schema

Non-canonical or unrecognized STEP is rejected with `firmament-inline-step-requires-aetheris-canonical-step`. User-facing diagnostics should direct authors to run `aetheris canon <input.step> --out <canonical.step>` first.

## Fixture

Valid wrapper fixture:

- `fixtures/FirmamentV2/InlineStep/valid/inline-step-v2-canonical-box-reexport-step-verified.valid.firmfixture`

Canonical input STEP fixture:

- `fixtures/FirmamentV2/InlineStep/testdata/canonical-box-10x8x6.step`

The input fixture is a 10 x 8 x 6 mm box generated by Aetheris, with expected volume `480`, `6` faces, `8` vertices, and `12` edges.

## Real importer/exporter path

The build path is intentionally not byte-preserving STEP editing:

```text
Firmament V2 InlineStep parse
  -> resolve fixture-relative STEP path
  -> verify Aetheris-canonical header evidence
  -> Step242Importer.ImportBody(...)
  -> BrepBody
  -> Step242Exporter.ExportBody(...)
  -> AP242 output
  -> Step242Importer.ImportBody(...) verification
```

The AP242 output is canonicalized and is not expected to be byte-identical to the input STEP.

## Verification checks

Tests verify that the output exists, contains AP242 topology markers (`ADVANCED_FACE`, `VERTEX_POINT`), is not trace-only, reimports through `Step242Importer`, and round-trips to the canonical box topology/volume.

## Deferred features

INLINE-STEP-X1 deliberately does not implement:

- arbitrary raw external STEP inline support;
- byte-preserving STEP edits;
- semantic PMI on imported topology;
- topology identity maps;
- recognition labels;
- replacement;
- residual accounting;
- graphical PMI;
- multiple imported bodies or assembly STEP support.
