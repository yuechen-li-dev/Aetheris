# AETHERIS-PANEL-M0 evidence

Generated by:

```powershell
dotnet run --project Aetheris.CLI -- modules showcase --out-dir docs/development/milestones/modules/artifacts/panel-m0
```

The semantic architecture is documented in [`../../panels.md`](../../panels.md). `canonical-panel.firmament` and `compiler-bridge.json` prove ordinary Firmament source -> typed surface construction -> Panel. `surfacing-gallery-inspection.json` contains the converted six-Panel M1 gallery with edge IDs, curve families, lengths, winding, construction family, exactness/approximation, developability, STEP hash, and reimport result.

`panel-network.json` contains the four-piece folded canopy: all pieces classify `Developable`, its three intentional opposite-direction seams have zero endpoint and G0 residual, and ten perimeter edges remain free. The four `developable-folded-canopy-*.step` files are separate pieces; no Boolean union or flat pattern is claimed.

`validation-report.json` records compiler, Panel construction, edge inspection, Mate validation, and STEP timings plus repeated Panel-ID determinism. Gallery and canopy STEP files are AP242 closed export envelopes because the current exporter accepts manifold-solid roots; `PanelIr` itself remains an open bounded engineering object. STEP reimport is recorded for every gallery entry.

Known bounded limitations: G1 is typed but unsupported; SurfaceMeshIR rejects non-rational B-spline supports; three-sided construction has no current honest M1 producer; AP242 does not preserve Panel semantics; no flat-pattern, SubD, SDF, Panel-specific Drawing, or Cadmata edge-highlight work was added.
